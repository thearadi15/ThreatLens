# Troubleshooting & Common Issues\n\n## Deployment Issues\n\n### \"Permission denied\" or \"Azure CLI not found\"\n```powershell\n# Install Azure CLI\nwinget install Microsoft.AzureCLI\n\n# Restart PowerShell and try again\naz login\n```\n\n### \"Resource already exists\" error\n```powershell\n# Check existing resources\naz resource list --resource-group threatlens-lab\n\n# Delete old group\naz group delete --name threatlens-lab --yes\n\n# Try deployment again\n.\\scripts\\deploy_infra.ps1\n```\n\n### \"Insufficient quota\" for VM size\n- Standard_D4s_v3 requires 4 cores\n- Azure for Students may have lower limits\n- Solution: Use smaller VM sizes in script\n```powershell\n# Edit deploy_vms.ps1, change \"Standard_D4s_v3\" to \"Standard_B2s\"\n```\n\n---\n\n## Bastion SSH Issues\n\n### \"Cannot connect via Bastion\"\n\n1. **Check VMs are running**\n```powershell\naz vm get-instance-view --resource-group threatlens-lab --name elk-siem --query \"instanceView.statuses[?starts_with(code, 'PowerState/')].displayStatus\"\n```\n\n2. **Check Bastion is deployed**\n```powershell\naz network bastion show --resource-group threatlens-lab --name threatlens-bastion\n```\n\n3. **Check NSG rules allow Bastion**\n```powershell\naz network nsg rule list --resource-group threatlens-lab --nsg-name attacker-nsg --query \"[].{Name:name, SourcePrefix:sourceAddressPrefix, Protocol:protocol, DestinationPort:destinationPortRange}\"\n```\n\n4. **Wait 3–5 minutes**\n   - VMs take time to fully boot and configure\n   - Try again in a few minutes\n\n### \"SSH key not found\"\n```powershell\n# Generate SSH keys if missing\nssh-keygen -t rsa -b 4096 -f ~/.ssh/id_rsa -N \"\"\n\n# Grant proper permissions\nls ~/.ssh/id_rsa\n```\n\n---\n\n## ELK Stack Issues\n\n### Elasticsearch not starting\n```bash\n# Check status\nsudo systemctl status elasticsearch\n\n# Check logs\nsudo journalctl -u elasticsearch -n 50\n\n# Restart\nsudo systemctl restart elasticsearch\n\n# Wait 30 seconds then check if running\nsleep 30 && curl http://localhost:9200/\n```\n\n### Kibana (port 5601) not accessible\n```bash\n# Verify Kibana is running\nsudo systemctl status kibana\n\n# Check it's listening\n$ sudo netstat -tlnp | grep 5601\n\n# Check logs\nsudo journalctl -u kibana -n 50\n\n# Verify it can reach Elasticsearch\ncurl http://localhost:9200/ # Should return JSON\n```\n\n### \"No data indexed\" in Kibana\n1. **Check Filebeat is shipping logs**\n```bash\n# On victim VM\nsudo systemctl status filebeat\nsudo tail -f /var/log/filebeat/filebeat\n```\n\n2. **Check Logstash is receiving**\n```bash\n# On SIEM VM\nsudo systemctl status logstash\nsudo tail -f /var/log/logstash/logstash-plain.log\n```\n\n3. **Verify network connectivity**\n```bash\n# From victim, ping SIEM\nping 10.0.3.4\n\n# From victim, check port 5044 is open\nnc -zv 10.0.3.4 5044\n```\n\n4. **Check Elasticsearch has indices**\n```bash\n# On SIEM VM\ncurl -u elastic:PASSWORD http://localhost:9200/_cat/indices\n```\n\n---\n\n## Service Issues\n\n### DVWA not loading (http://victim-ip/dvwa/)\n```bash\n# Check Apache\nsudo systemctl status apache2\n\n# Check PHP\nphp -v\n\n# Verify DVWA files\nls -la /var/www/html/dvwa/\n\n# Check Apache logs\nsudo tail -f /var/log/apache2/error.log\n```\n\n### SSH login fails\n```bash\n# Verify sshd is running\nsudo systemctl status ssh\n\n# Check SSH config\nsudo grep \"PasswordAuthentication\" /etc/ssh/sshd_config # Should be \"yes\"\n\n# Restart SSH\nsudo systemctl restart ssh\n\n# Verify user exists\nid labuser\n\n# Reset password\necho \"labuser:password123\" | sudo chpasswd\n```\n\n### FTP not accessible\n```bash\n# Check vsftpd running\nsudo systemctl status vsftpd\n\n# Check FTP logs\nsudo tail -f /var/log/vsftpd.log\n\n# Test locally\nftp localhost\n```\n\n---\n\n## Attack Tool Issues\n\n### Nmap not installed\n```bash\nsudo apt install -y nmap\nnmap --version\n```\n\n### Hydra connection refused\n```bash\n# Verify victim is reachable from attacker\nping 10.0.2.4\n\n# Check SSH is running on victim\nssh labuser@10.0.2.4 -v  # -v for verbose\n```\n\n### Metasploit won't start\n```bash\n# Re-install\ncurl https://raw.githubusercontent.com/rapid7/metasploit-omnibus/master/config/templates/metasploit-framework-wrappers/msfupdate.erb > ~/msfinstall\nchmod 755 ~/msfinstall\nsudo ~/msfinstall\n\n# Or use community edition\nsudo apt install -y postgresql\nsudo msfconsole\n```\n\n---\n\n## Network Issues\n\n### VMs can't reach each other\n```bash\n# From attacker, test connectivity to victim\nping 10.0.2.4\nnc -zv 10.0.2.4 22  # Test SSH port\n\n# From victim, test connectivity to SIEM\nping 10.0.3.4\nnc -zv 10.0.3.4 5044  # Test Logstash port\n```\n\n### Logs not flowing Victim → SIEM\n1. **Check NSG rules allow** Beats (port 5044)\n```powershell\naz network nsg rule show --resource-group threatlens-lab --nsg-name victim-nsg --name allow-beats-to-siem\n```\n\n2. **Verify SIEM IP** in Filebeat config\n```bash\n# On victim\nsudo cat /etc/filebeat/filebeat.yml | grep \"hosts:\"\n# Should be: hosts: [\"10.0.3.4:5044\"]\n```\n\n3. **Restart Filebeat**\n```bash\nsudo systemctl restart filebeat\nsleep 5\nsudo systemctl status filebeat\n```\n\n---\n\n## Cost Issues\n\n### \"My Azure bill is too high\"\n1. **Check running VMs**\n```powershell\naz vm get-instance-view --resource-group threatlens-lab --name elk-siem --query \"instanceView.statuses[?starts_with(code, 'PowerState/')].displayStatus\"\n```\n\n2. **Stop (deallocate) VMs if not using**\n```powershell\naz vm deallocate --resource-group threatlens-lab --name elk-siem\n```\n\n3. **Delete entire lab to stop charges**\n```powershell\naz group delete --name threatlens-lab --yes\n```\n\n---\n\n## Getting Help\n\n1.
